# Критические уязвимости и Технический долг (Reality Check v0.4)

> **Статус:** ОБЯЗАТЕЛЬНО К ИСПРАВЛЕНИЮ.
> **Назначение:** Единый реестр проблем, найденных в ходе аудита репозитория (движок, бэкенд, фронтенд, БД).
> **Инструкция:** Задачи с пометкой 🔴 блокируют выход в прод. 🟡 — требуют внимания в ближайшие итерации. 🟢 — плановый рефакторинг.

## ✅ КРИТИЧНО: Безопасность и Целостность данных (ЗАКРЫТО)

### ✅ 1.1. Подделка идентичности (UserGuard) — РЕШЕНО
- **Файл:** `apps/backend/src/common/user.guard.ts`, `webway-session.ts` (новый)
- **Решение:** Серверная валидация session-cookie через Redis, заголовки `x-user-id`/`x-user-is-admin` полностью игнорируются. `isAdmin` берётся только из БД. Fail-closed при недоступности Redis/БД.
- **Статус:** ✅ Закрыто в итерации 4.1

### ✅ 1.2. Мутация чужого матча через тело запроса (IDOR) — РЕШЕНО
- **Файлы:** `apps/backend/src/matches/matches.service.ts`
- **Решение:** Публичный путь `save()` отбрасывает `player1Id`/`player2Id` из DTO, использует авторизованный userId. Серверный путь `saveFromServer()` для доверенных вызовов. Валидация `winnerId`.
- **Статус:** ✅ Закрыто в итерации 4.1

### ✅ 1.3. Race condition в состоянии комнат — РЕШЕНО
- **Файлы:** `apps/backend/src/rooms/rooms.service.ts`
- **Решение:** Distributed lock `SET NX PX 3000` (`aspects:room_lock:<code>`) с `withRoomLock()` (retries + jitter). Lua-скрипт для атомарного release-lock. Все конкурентные пути приведены к единому протоколу.
- **Статус:** ✅ Закрыто в итерации 4.1

### ✅ 1.4. Утечка памяти при сохранении команд — РЕШЕНО
- **Файлы:** `apps/backend/src/rooms/rooms.service.ts`
- **Решение:** История команд вынесена в Redis-лист (`RPUSH`), `save()` больше не сериализует команды. Батчинг `createMany` по 500 строк в Prisma. Debounce online-status (5 секунд).
- **Статус:** ✅ Закрыто в итерации 4.1

## 🟡 ВАЖНО: Производительность и Архитектура

### 2.1. Блокировка Redis (операция `KEYS`)
- **Файлы:** `rooms.service.ts` (timer-check), `matchmaking.service.ts` (tryMatch, tryFallbackToBot), `socket-io.ts` (bot-loop)
- **Проблема:** Использование блокирующей операции `redis.keys('aspects:room:*')` в циклах, запускаемых каждые 5 секунд и 500 мс. Это блокирует весь Redis-сервер на время сканирования (O(N)).
- **Решение:** Заменить `KEYS` на `SCAN` или хранить список активных комнат/очередей в отдельном Redis Set'е (`SADD`, `SMEMBERS`). Применять `MGET`/pipeline для чтения состояний нескольких комнат.

### 2.2. Мёртвый код легаси-констант
- **Файл:** `packages/cards/src/loader.ts` (строки 331-347)
- **Проблема:** Константы `ALL_CARDS`, `STORMWIND_ASPECTS`, `VOIDFLAME_ASPECTS`, `LEGENDARY_ASPECTS`, `TOKEN_ASPECTS` ссылаются на несуществующие `meta.id` (например, `PACKS.stormwind`, хотя реальный `id` — `ash_stormwind`). Не используются в продакшн-коде, только в тестах движка.
- **Решение:** Удалить неиспользуемые константы. Для тестов заменить использование легаси-констант на актуальные функции загрузки карт (`mergedCards`, `getCards`).

### 2.3. Мёртвый и небезопасный WebSocket-слой GameGateway
- **Файлы:** `apps/backend/src/rooms/game.gateway.ts`, `rooms.module.ts`
- **Проблема:** Файл содержит мёртвый код (не зарегистрирован в модуле как активный шлюз, либо дублирует логику основного `socket-io.ts`), который реализует небезопасную логику: идентификация по заголовку handshake, эмит полного состояния игры (спойлер-читинг, раскрытие рук соперника) и отсутствие сохранения рейтинга.
- **Решение:** Полностью удалить файл `game.gateway.ts` и связанные с ним импорты, оставив единственный рабочий слой `rooms/socket-io.ts`.

### 2.4. God-файл `socket-io.ts`
- **Файл:** `apps/backend/src/rooms/socket-io.ts` (~985 строк)
- **Проблема:** Смешение бизнес-логики, обработки команд, таймеров, бот-лупов, сохранения матчей и обновления рейтинга в одном файле с множеством `setInterval`.
- **Решение:** Разбить на отдельные сервисы: `RoomsGateway` (обработка сообщений), `TurnTimerService` (таймеры), `BotLoopService` (действия ботов), `MatchFinishService` (сохранение матча и рейтинг).

### 2.5. Консистентность типов (`RoomState`, `Command`)
- **Файлы:** `packages/shared/src/online.ts`, `packages/engine/src/types/state.ts`, `apps/backend/src/rooms/*`
- **Проблема:** Поле `gameState` в shared-типах определено как `unknown`, что заставляет бэкенд делать unsafe-касты (`as GameState`). Широко используется тип `any` в мапперах матчей.
- **Решение:** Ввести generic-алиасы для типизации состояния комнат. Заменить `any` на конкретные типы из `@aspects/engine` и `Prisma`.

### 2.6. Неправильное логирование ошибок
- **Файлы:** `rooms/socket-io.ts` (~30 мест), `matchmaking.service.ts`, `session.controller.ts`
- **Проблема:** В критическом слое обработки сокетов используется `console.error/log` вместо NestJS Logger. В некоторых местах ошибки проглатываются молча (`catch(() => {})` или `.catch(() => null)`).
- **Решение:** Инжектировать `Logger` в сервисы, заменить все `console.*`. В пустых catch-блоках добавить минимальное логирование (`logger.debug/warn`).

### 2.7. Безопасность анонимных cookie
- **Файлы:** `common/anon-cookie.ts`, `main.ts`
- **Проблема:** Анонимные cookie читаются вручную без проверки подписи. Существует хардкодный fallback-секрет `'aspects-internal'` в коде.
- **Решение:** Не полагаться на целостность аноним-ID для критических операций. Удалить default-секрет (fail-fast при отсутствии `env`).

## 🟢 ЗАМЕЧАНИЯ: Рефакторинг и Стиль

### 3.1. Генерация кодов комнат и Seed
- **Проблема:** `Math.random()` не крипто-стойкий, коллизии не проверяются. `Date.now() + Math.random()` не идеален для детерминизма.
- **Решение:** Использовать `crypto.randomInt` + проверку существования ключа. Для seed использовать `crypto.randomUUID()`.

### 3.2. Раздувание БД (`cardSnapshot`)
- **Проблема:** `cardSnapshot` сохраняется полностью для каждого матча в Prisma, что ведёт к разрастанию БД.
- **Решение:** Хранить только ID версий паков/карт, либо использовать сжатие JSON.

### 3.3. Frontend: Дублирование тултипов
- **Проблема:** Три дублирующие реализации тултипов: `CardTooltipDef`, `HoverTooltip`, `CardTooltip`.
- **Решение:** Объединить в один универсальный компонент `<CardTooltip variant="def | instance" />`.

### 3.4. Frontend: Мобильная адаптация
- **Проблема:** 5-колоночная доска и декбилдер не адаптированы под узкие экраны (360px). `HoverTooltip` не работает на тач-устройствах.
- **Решение:** Добавить медиа-запросы, горизонтальный скролл для доски, переключение тултипов на модальные окна по тапу.

### 3.5. Отсутствие Health Check
- **Проблема:** Отсутствует readiness-проба для Prisma/Redis.
- **Решение:** Добавить проверку подключения к внешним зависимостям при старте и в `/health` эндпоинте.
