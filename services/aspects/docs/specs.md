> **Статус:** Закрытая Бета / Early Access.
> **Обновлено:** После полного Reality Check (глубокий аудит движка, бэкенда, фронтенда, БД и репозитория).
> **Назначение:** Единый документ для онбординга новых сессий (Родительская, Бот-сессия, Баланс-сессия, Бэкенд-сессия, UI-сессия).

## 1. Обзор проекта

**Что:** Веб-ККИ для 2 игроков (1v1) с 5-колоночным полем и нейтральными клетками, дающими бонусы. Полностью авторская система с механикой замены аспектов одной личности.

**Кто:** Solo-разработчик. Активно использует параллельные AI-сессии:
- **Родительская** (архитектор, координатор, приёмщик)
- **Бот-сессия** (ИИ, алгоритмы, профили)
- **Баланс-сессия** (карты, пресеты, лор, мета)
- **Бэкенд-сессия** (инфраструктура, безопасность, БД)
- **Бот-агент с доступом к репозиторию** (глубокий аудит и ревью)

**Где:** `D:\Anathema\services\aspects` — часть большого проекта **Anathema** (Discord-бот + веб-панель Webway).

**Ключевые принципы:**
- Детерминизм движка (seed + команды → воспроизводимые партии)
- Сервер авторитетен (клиент шлёт `Command`, сервер применяет через `applyCommand`)
- Монорепа pnpm + TypeScript, пакеты CJS (не ESM)
- Итеративная разработка, фичи на 1-2 дня
- **Мета-инструменты:** Пакет `@aspects/simtools` содержит 22 скрипта для анализа баланса, поиска дублей и калибровки ботов. Полная документация в `docs/simtools-reference.md`.

## 2. Инфраструктура

### 2.1. Монорепа
`package.json` в корне, `pnpm-workspace.yaml`:
```yaml
packages:
  - 'apps/*'
  - 'packages/*'
```
Общий `tsconfig.base.json`, каждый пакет расширяет его.
Пакеты CJS: `module: CommonJS`, `moduleResolution: Node`.
Vite alias на `src` (не `dist`) для фронтенда.

### 2.2. Пакеты и зависимости
```
shared ← cards ← engine ← bot ← simtools
                                  ↓
                              backend
frontend → engine, cards, bot, shared
```
`@aspects/shared` не должен импортить из `@aspects/cards` (риск циклических зависимостей).

| Пакет | Путь | Роль |
|---|---|---|
| `@aspects/shared` | `packages/shared/` | Общие типы, zod-схемы, валидация колод, утилиты |
| `@aspects/cards` | `packages/cards/` | Данные карт, схема, загрузчик, скопы, генератор индекса паков |
| `@aspects/engine` | `packages/engine/` | Чистый движок правил, детерминизм, валидация на границе |
| `@aspects/bot` | `packages/bot/` | ИИ (Heuristic, Greedy, MCTS), профили, уровни сложности |
| `@aspects/simtools` | `packages/simtools/` | Симуляции, статистика, мета-инструменты (23 скрипта) |
| `@aspects/backend` | `apps/backend/` | NestJS + Fastify + Prisma + Redis + Socket.io |
| `@aspects/frontend` | `apps/frontend/` | React + Vite, SPA под `/games/aspects/` |

Ключевые файлы внутри пакетов
- `@aspects/engine`: `src/commands/applyCommand.ts` (entry point), `src/state/create.ts`, `src/state/helpers.ts`, `src/abilities/effectResolver.ts`, `src/types/events.ts`.
- `@aspects/cards`: `src/loader.ts`, `src/scopes.ts`, `src/schema.ts`, `src/data/packs/`.
- `@aspects/backend`: `src/rooms/socket-io.ts` (основной шлюз), `src/rooms/rooms.service.ts`, `src/matchmaking/matchmaking.service.ts`, `src/matches/matches.service.ts`.

### 2.3. Сборка (Строгий порядок!)
```bash
pnpm --filter @aspects/shared build
pnpm --filter @aspects/cards build
pnpm --filter @aspects/engine build
pnpm --filter @aspects/bot build
pnpm --filter @aspects/simtools build
pnpm --filter @aspects/backend build
pnpm --filter @aspects/frontend build
```
Порядок обязателен: `engine` видит типы из `cards` только после сборки `cards`.
`@aspects/cards` имеет `prebuild` хуки: `validate` (zod-валидация) и `gen:packs` (генерация `packs-index.generated.ts`).

## 3. `@aspects/cards` — данные карт (Реальное состояние)

### 3.1. Статистика контента (Аудит от 30.10.2026)
- **Всего карт:** 355 (включая 21 токен).
- **Уникальных личностей:** 270.
- **Пресетов:** 13 готовых колод.
- **Кривая маны (Внимание: Midrange перекос!):**
  - Cost 0: 21 | Cost 1: 24 (Мало для Aggro!)
  - **Cost 2-4: 244 карты** (Огромное ядро для Midrange/Value)
  - Cost 5+: 66 карт
- **Редкости:** common: 83, uncommon: 122, rare: 92, epic: 18, legendary: 40 (~11%).

### 3.2. Паки и Скопы
В игре **14 серий**, распределённых по 3 скопам:
- **`main`** (primary, баланс фокус): `classic`, `cradle`, `inner`, `throne`, `integration`, `cathedral`.
- **`ashenlight`**: `ash_stormwind`, `voidflame`, `forsaken`, `apocryph`.
- **`oskol`**: `perimeter`, `razlom`, `echo`, `sky`.

Колода целиком должна лежать в одном скопе. Смешивание серий разных скопов запрещено.

### 3.3. Топ-личности (Готовые архетипы для Aspect-Shift)
- `temporal` (8 аспектов), `yuoko` (8 аспектов), `alt` (7 аспектов)
- `gorox`, `spy`, `inki`, `hyper`, `hacker`, `safno`, `zamiatish` (по 5 аспектов).

### 3.4. Загрузчик и Генерация
- `loader.ts` нормализует теги, фракции и роли карт при загрузке.
- `scripts/gen-packs-index.mjs` рекурсивно сканирует `src/data/packs/*/` и генерирует `packs-index.generated.ts`, избавляя от ручных импортов.
- `active-series.json` управляет видимостью серий в декбилдере.

## 4. `@aspects/engine` — движок правил

### 4.1. Ключевые типы и правила (v0.4)
- **Glory:** 25 (было 30 в ранних итерациях).
- **Despair:** Отключено (нет авто-выхода резервов при низком здоровье).
- **Alt-victory:** Мгновенная победа при захвате 5/5 нейтралов.
- **Underdog:** Добор карт отключён (защита от hand bloat). Влияние +1 остаётся.
- **Замена:** Реализована со скидкой `min(floor(old_cost/2), floor(new_cost/2))`.
- **Стартовая рука:** 4 карты. Одна карта с `starter` гарантированно попадает в руку до муллигана.
- **Лимиты колоды:** 30 карт, ≤5 копий личности, ≤2 копии аспекта, ≤1 легендарки, ≤4 серий.

### 4.2. Валидация на границе
Движок (`create.ts`) проверяет только базовые лимиты (размер колоды и легендарки). Полная валидация правил декбилдинга выполняется на уровне `@aspects/shared` (`validateDeck`) до передачи колоды в движок. Движок считает входные данные корректными.

### 4.3. Поддерживаемые механики
- **Ключевые слова:** `charge`, `taunt`, `scout`, `breakthrough`, `shield`, `suppress`, `armored`, `regenerate`, `cleave`, `frenzy`, `starter`, `slow`, `vanguard`, `temporary`.
- **Триггеры:** `ON_ENTER`, `ON_EXIT`, `ON_REINFORCE`, `ON_REPLACE`, `ON_TURN_START`, `ON_TURN_END`, `ON_THIS_DAMAGED`, `ON_ALLY_ATTACKED`, `ON_ENEMY_ATTACK`, `ON_ALLY_DIED`, `ON_ATTACK`, `ON_KILL`, `ON_CELL_CAPTURED`, `ON_CELL_LOST`, `ON_DAMAGE_DEALT`, `ON_CARD_DRAWN`.

- **Эффекты:** Урон, лечение, баффы, добор, влияние, сброс (случайный/выбранный), призыв токенов, перемещение, сайленс, истощение, выбор целей (`CHOOSE_TARGETS_THEN`).
- **Условия:** Композитные `AND`, `OR`, `NOT`, фильтры по тегам, стоимости, силе, наличию щита.

## 5. `@aspects/bot` — ИИ

### 5.1. Реализации и Уровни
- **Профили:** balanced, aggro, defensive, control, opportunist, berserker.
- **Уровни:** rookie, novice, regular, veteran, master, grandmaster (всего 36 комбинаций).
- **Feature Flags:** `smartMulliganV2`, `smartReplace`, `column5Penalty`, `smartDiscard`, `lateGameNeutralFix`, `v4Attack`, `v4Triggers`, `v4ReplaceV2`, `smartAbility`, `v5AltVictory`.

### 5.2. Важное изменение в Бот-сессии
Флаг `v5AltVictory` **включён** для уровней `master` и `grandmaster` (вопреки старым спекам, где он был отключён). `v5Lookahead` остаётся экспериментальным и не используется по умолчанию.

### 5.3. Калибровка силы
Боты калибруются через `tournament.ts` (1200 партий), что позволяет матчмейкингу подбирать бота, идеально подходящего под текущий скилл игрока.

## 6. `@aspects/simtools` — мета-инструменты

Пакет содержит **22** CLI-скрипта для анализа меты и баланса.

**Ключевые инструменты:**
- `pace-report`: Длина партии, hand bloat, причины победы. **Актуальные цифры:** Mean turns 26.2, Median 24, Alt-victory 21.6%.
- `attack-efficiency`: Куда уходят атаки (direct, kill, trade, chip, neutral).
- `card-stats`: Δ-метрика (разница винрейта с картой и без неё).
- `replacement-analysis`: Анализ использования механики замены.
- `card-overlap`: Поиск механических дублей карт (статический анализ).
- `matrix`, `duel`: Матрицы винрейтов и дуэли между ботами/колодами.
- `find-long-games`: Поиск затянувшихся партий для анализа усталости.
- `deck-optimizer`: Генетический поиск оптимальных колод.

**Полная документация:** `docs/simtools.md` (v0.4).

## 7. `@aspects/backend` — сервер и инфраструктура

### 7.1. Стек и БД
NestJS + Fastify, Prisma (PostgreSQL `anathemaaspects`), Redis (db 1 для комнат, db 0 для сессий).

### 7.2. Комнаты и Игровой процесс
- **Хранение:** Состояние комнаты хранится в Redis с TTL 1 час.
- **Таймеры:** 45 секунд на муллиган, 90 секунд на ход. При отключении игрока таймер останавливается (механика Takeover).
- **Безопасность сессий:** WebSocket аутентификация через куки/заголовки, пробрасываемые прокси.
- **Takeover:** Механика перехвата места отключившегося игрока.
- **Зрители (Spectators):** Поддержка наблюдения за матчем без права отправки команд.

### 7.3. Матчмейкинг и Рейтинг
- **Рейтинг:** Glicko-2 (для игроков и ботов).
- **Матчмейкинг:** Очереди в Redis Sorted Sets, разделённые по сериям.
- **Bot Fallback:** Если игрок ждёт >15 сек, ему подбирается бот. Окно поиска по рейтингу расширяется от ±200 до ±800 ELO.

### 7.4. Сохранение матчей и Реплеи
Модели `Match`, `MatchDeck`, `MatchCommand` сохраняют каждую команду матча с `sequence`. Это позволяет воспроизводить партии детерминированно через `applyCommand`.

### 7.5. Социалка
Модели `Friendship`, `UserProfile`, `UsersSearch`, `Leaderboard`. Канонические пары `userA < userB` защищают от дублей заявок.

## 8. `@aspects/frontend` — клиент

### 8.1. Архитектура и Роутинг
`useScreenRouting` управляет состояниями: Профиль, Настройка, Игра, Декбилдер, История, Реплей, Онлайн-лобби, Матчмейкинг, Поиск пользователей, Лидерборд, Профиль игрока, Друзья.

### 8.2. Игровой процесс (Уникальные фичи)
- **Замена в 1 клик:** Игрок кликает карту в руке, затем цель на доске. Если цель одна — замена происходит мгновенно, без модалки.
- **PassOverlay:** Экран передачи хода в хотсит-режиме (защита от подглядывания).
- **Выбор целей (`ChoicePrompt`):** Поддержка всех видов сброса и выбора целей, включая обязательные сбросы без права отмены.
- **Активируемые способности:** Иконка `⚡` на слоте карты с обработкой клика.

### 8.3. Декбилдер
Полноценный редактор колод с валидацией на клиенте, кривой маны, фильтрами по редкости/личности/роли/фракции и обработкой "битых" колод (с удалёнными картами).

## 9. Архитектурные решения (Не пересматривать)

1. **Сервер авторитетен.** Клиент шлёт `Command`, сервер применяет через `applyCommand`.
2. **Персональная рассылка state.** Чужая рука скрыта (кроме зрителей).
3. **Детерминизм движка** через seed + команды. Реплеи бесплатны.
4. **Валидация на границе:** `@aspects/shared` проверяет лимиты колоды, движок доверяет входу.
5. **Матчмейкинг разделён по сериям:** Игроки разных скопов не встречаются друг с другом.
6. **Bot Fallback с расширяющимся окном:** Игрок всегда находит игру, начиная с равного бота.

## 10. Известные архитектурные долги и уязвимости
*(Полный список с файлами и решениями находится в `security-and-debts.md`)*

1. **Безопасность (Критично):** `UserGuard` доверяет HTTP-заголовкам без подписи.
2. **IDOR:** Сохранение матчей принимает `player1Id` из тела запроса без проверки.
3. **Производительность:** Использование блокирующей `redis.keys('*')` в циклах матчмейкинга.
4. **Кодовая база:** `socket-io.ts` — God-файл на ~985 строк. Мёртвый `game.gateway.ts`. Дублирование тултипов на фронте.

## 11. Подводные камни и Стиль работы

- **Сборка:** Строгий порядок пакетов. При добавлении нового пакета в бэкенд — править `Dockerfile`.
- **Детерминизм:** Никаких `Math.random()` в engine, cards, bot (кроме скриптов-утилит).
- **Документация:** Не оставлять `title`, `shortDescription`, `lore` пустыми даже у токенов.
- **Роли сессий:** Родительская не пишет весь код сама, а ставит ТЗ суб-сессиям и ревьюит их работу.
