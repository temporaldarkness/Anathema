# Roadmap: Итерация 4 (Post-Reality Check)

> **Стратегия:** «Разделяй и властвуй».
> **Статус:** Готово к запуску. Все задачи сформированы на основе полного аудита репозитория.
> **Приоритет:** 🔴 Безопасность → 🟡 Мета/Баланс → 🔵 ИИ → 🟢 Рефакторинг/UX.

## 🎯 Обзор стратегии

Проект вышел из стадии прототипирования. Ядро правил, движок и базовая инфраструктура работают стабильно. 
**Фокус 4-й итерации:**
1. Закрыть критические дыры в безопасности бэкенда.
2. Исправить перекос меты в сторону Midrange (добавить инструменты для Aggro).
3. Научить ИИ глубже понимать механику Aspect-Shift.
4. Подготовить клиент к притоку новых игроков (мобильная версия, туториал).

## 🔴 Стрим 1: Бэкенд и Безопасность (Запускается ПЕРВЫМ)

**Цель:** Устранить уязвимости, найденные агентом-аудитором. Без этого стрима нельзя деплоить в прод.

**ТЗ для Бэкенд-сессии:**
1. **Фикс IDOR в матчах:**
   - В `matches.service.ts` игнорировать `player1Id`/`player2Id` из DTO.
   - Сервер должен сам определять ID игрока из контекста авторизации (`req.user.id`).
   - Добавить валидацию `winnerId`.
2. **Фикс UserGuard:**
   - Убрать доверие к заголовкам `x-user-id`, `x-user-is-admin`.
   - Перейти на проверку подписи сессии или мТLS.
3. **Устранение Race Conditions:**
   - Внедрить Redis Locks (как в `game.gateway.ts`) во все пути записи комнат (`save()`).
   - Либо использовать Lua-скрипт с CAS (Compare-And-Swap).
4. **Оптимизация Redis:**
   - Заменить `redis.keys('*')` на `SCAN` в `matchmaking.service.ts` и `rooms.service.ts`.
   - Вести отдельный Set активных ключей.
5. **Рефакторинг God-файла:**
   - Вынести таймеры, бот-лупы и сохранение матчей из `socket-io.ts` в отдельные сервисы.

**Ожидаемый результат:** Бэкенд проходит внутренний аудит безопасности, нет критических дыр в логах.

---

## 🟡 Стрим 2: Баланс и Мета (Запускается ПАРАЛЛЕЛЬНО с Бэкендом)

**Цель:** Исправить перекос кривой маны и поддержать альтернативные пути победы.

**Данные аудита:** В игре 355 карт, но только 24 карты стоят 1 ману. Ядро меты — это 244 карты за 2-4 маны.

**ТЗ для Баланс-сессии:**
1. **Aggro-инъекция:**
   - Создать 10-15 карт стоимости **1 мана**.
   - Обязательные механики: `charge`, `frenzy`, `scout`.
   - Запрещено: две карты с 2+ keywords на 1 мане (кроме 1/1).
2. **Пейоффы для Alt-Victory:**
   - Создать 3-4 карты с мощными триггерами `ON_CELL_CAPTURED`.
   - Цель: поднять винрейт альтернативной победы с 12.5% до ~18%.
3. **Аудит Топ-личностей:**
   - Проверить `temporal`, `yuoko`, `alt` на наличие имбалансных связок.
   - При необходимости перераспределить аспекты или изменить их роли.
4. **Выравнивание пула:**
   - Создать новые аспекты для личностей, у которых сейчас только 1-2 карты.

**Ожидаемый результат:** Новая серия карт (или расширение текущих), закрывающая дыры в Aggro и Alt-Victory архетипах.

---

## 🔵 Стрим 3: Интеллект ИИ (Запускается после Баланса)

**Цель:** Научить бота планировать замены и лучше использовать топ-личностей.

**ТЗ для Бот-сессии:**
1. **Aspect-Shift Lookahead:**
   - Научить `HeuristicBot` понимать, что держать в руке второй аспект личности как тактический резерв — выгодно.
   - Доработать `scoreReplaceCardV2` с учётом планирования на 2-3 хода вперёд.
2. **Калибровка силы:**
   - Прогнать `tournament.ts` с включённым/выключенным `v5AltVictory` для уровней `master` и `grandmaster`.
   - Обновить комментарии в `bot-factory.ts` по результатам теста.
3. **Оптимизация бот-комнат:**
   - Улучшить логику `buildBotDeck`, чтобы боты не собирали заведомо проигрышные колоды из малых пулов карт.

**Ожидаемый результат:** Боты играют осмысленнее, используют замены по назначению, турнирные рейтинги стабильны.

## 🟢 Стрим 4: UX и Клиент (Запускается по мере необходимости)

**Цель:** Сделать игру доступной на мобильных устройствах и понятной для новичков.

**ТЗ для UI-сессии:**
1. **Мобильная адаптация:**
   - Добавить медиа-запросы в `styles/` для экранов шириной 360px.
   - Реализовать горизонтальный скролл или компактный режим для `Board.tsx`.
   - Заменить `HoverTooltip` на модальные окна по тапу.
2. **Объединение тултипов:**
   - Слить `CardTooltipDef`, `HoverTooltip` и `CardTooltip` в один универсальный компонент.
3. **Туториал:**
   - Создать интерактивный `TutorialScreen`.
   - Объяснить: что такое Нейтралы, как работает Замена, зачем нужны Фазы.

**Ожидаемый результат:** Игра стабильно работает на телефонах, новый игрок понимает базовые правила за 5 минут.

## 🟢 Стрим 5: Рефакторинг и Долги (Фоновый режим)

**Цель:** Вычистить кодовую базу и подготовить её к масштабированию.

**ТЗ для Ревизора / Рефакторинг-сессии:**
1. **Удаление мёртвого кода:**
   - Удалить `game.gateway.ts`.
   - Удалить легаси-константы из `loader.ts` (`ALL_CARDS`, `STORMWIND_ASPECTS` и т.д.).
   - Удалить `docker-compose.yml.save`.
2. **Оптимизация БД:**
   - Пересмотреть хранение `cardSnapshot` в матчах (возможно, хранить только ID версий).
3. **Логирование:**
   - Заменить все `console.*` на NestJS `Logger`.
4. **Тесты:**
   - Написать недостающие тесты на скидку замены и новые механики (`cleave`, `frenzy`, `silence`).

**Ожидаемый результат:** Кодовая база чище, нет дублирования, сборка стабильна.

## 🚀 Порядок запуска и Критерии завершения

**Порядок:**
1. **Неделя 1:** Запуск Стрима 1 (Бэкенд). Параллельно — Стрим 2 (Баланс).
